# Trello dashboard

The list-by-list reference for the Trello board the PFC system renders to. Root [`AGENTS.md`](../AGENTS.md) § "Trello dashboard" has the summary; read this page before changing anything that renders to Trello. Setup: [`install/trello.md`](install/trello.md).

The PFC system mirrors to a Trello board (id in `TRELLO_DASHBOARD_BOARD_ID`) so you can see the whole system at a glance from your phone. Repo is canonical; Trello is a rendered cache for read-only lists, with a thin write-back path for cards you check off or tick from the mobile app.

## Skills and render triggers

Three skills + one helper script:

- **`pfc-trello-inbox`** — process the `📥 Inbox` list. You dictate quick captures from a phone widget; the skill walks each card, treats the title as if you had typed it in chat, runs the natural action, deletes the card. Cards also come from the reMarkable `0 - Inbox` page when the tablet pages are on ([`remarkable.md`](remarkable.md)). Optionally, a server timer runs it unattended every 10 minutes (`scripts/trello-inbox-auto.sh`, opt-in with `PFC_TRELLO_INBOX=1` in `.env`): a clear card is carried out and deleted; an unclear one is renamed `❓ <title>` with its question in the description and waits for an interactive run.
- **`pfc-render-trello`** — refresh every dashboard list from current repo state. Idempotent; running twice = 0 changes. Auto-fetches Calendar (primary + work) via MCP; the week surface hides PFC scaffolding, routines and known weekly patterns while keeping their one-off exceptions (`config/trello_calendar_filters.yaml`). Includes `--rebuild` for full re-creation and `--reset-list <name>` for single-list resets, both confirmation-gated. The `📥 Inbox` list is hard-excluded from every render and rebuild. Auto-invoked as a fail-safe step (any error logs 🟡 and continues; never blocks anything) on three triggers:
  - **Calendar-fetching renders (`🗓️ Week` from a live fetch)** — the one path that fetches Calendar via MCP before rendering: `pfc-render-trello` (manual or on demand; `/pfc-review` and `/pfc-yearly-checkin` call it too).
  - **Bare skill-driven renders (`🗓️ Week` from the cache)** — wired as a fail-safe end-step but run the bare `trello_render.py` (no MCP fetch), so they build `🗓️ Week` from `data/calendar-cache.json`: every `pfc-add-task` / `pfc-add-project` / `pfc-add-vision` run, `pfc-focus`, `pfc-complete-task`, `pfc-log-habit`, `pfc-log-day`, and `pfc-sync-trello` (when counters show writes).
  - **Git post-commit hook** — `.githooks/post-commit` (installed at `.git/hooks/post-commit`) catches ad-hoc edits that bypass skills: raw `jq` updates, manual file edits, agent edits, anything else that commits a rendered file. `🗓️ Week` comes from the cache (no MCP data in a hook). Opt-out: `PFC_SKIP_TRELLO_RENDER=1 git commit ...`.

  Only the Calendar-fetching path reads a live calendar; every other render builds `🗓️ Week` from `data/calendar-cache.json`, which `/pfc-render-trello` Step 1 writes (the optional daily sync job runs that step alone each morning, [`install/daily-sync.md`](install/daily-sync.md)). With no usable cache (`--no-calendar-cache`, or a cache over 7 days old) the week cards are left as they are. (Email is no longer a rendered list — labeled emails become tasks via `pfc-email-triage` Step 0.)
- **`pfc-sync-trello`** — process cards you marked complete (`dueComplete: true`). For tasks: marks done in repo, archives card. For habits: appends a habit-log entry, leaves the card to cycle on next render. Idempotent. The daily sync job runs it each morning when installed (`scripts/daily-sync.sh`, which calls `trello_writeback.py sync`). When run standalone with non-zero counters, also auto-renders the board so card state catches up.
- **Three write-backs commit their own file.** The rating card (`data/day-tracking.ndjson`, `track: log day <date>`), a dropped pick and the auto-pick (`6-tasks/_data/daily-focus.ndjson`, `focus: set <date> (dropped on Trello)` / `(auto-pick)`) are committed by path and pushed by `trello_writeback.GitCommitter` wherever the sync runs, because a change left uncommitted would block the web writer and stop a server clone's fast-forward. Each writes only on the write branch (`PFC_WRITE_BRANCH`, default `main`) and only while that file has no uncommitted edits; otherwise it waits for a later run. Task and habit write-backs leave their files for the caller (the skill, or the daily sync job) to commit.

## Lists

The board follows the web home page (`web/src/pages/index.astro`): the same bands in the same order and the same groups, `📥 Inbox` first and the web's other page, Tasks, last. Every render puts the lists in this order right after `📥 Inbox` (`ALL_LIST_NAMES` and `ensure_lists` in `trello_render.py`); a list the render does not name stays where it is. Cards built from the web's data come from one `home_data.build_home` call per render (`trello_home.py`), the same dict the web page and the TRMNL screens (`trmnl_home.py`) read, so no number or light can differ; when `build_home` fails, the render leaves those cards as they are (`trello_home.HOME_TYPES`) instead of emptying them. Every list is held in order by `Card.pos`, red first where it carries lights, and greens fold into one card where the web folds them.

- `📥 Inbox` (managed by `pfc-trello-inbox`, never touched by render).

**Today**

- `🦸 Body first` — the web Body first band, in this order:
  - **`🤖 Brief · <Mon Jan 6> · updated <2:05 PM>`** — the first card (`Card.pos` 1), the whole day on one card for a proactive agent that reads the board every few hours and cannot read the repo (for example a Claude Duet routine, [`duet/pfc-operator/SKILL.md`](duet/pfc-operator/SKILL.md)). Built by `trello_home.render_brief` from the same `build_home` call plus `trello_render.daily_habit_counts`. Plain labelled lines: `Rating:` (the day the home page rates, rated or not), `2+1 today` (titles, done or not), `Habits today` (done today, the ones not ticked yet, then each habit's past-7-days count), `Pulse:` (the Body first verdict), `Red:` (up to 5 red titles across Focus, Projects, Areas, Household and Trends, then a count of the rest), `Review now:` (the one review every surface shows now, from `review_forms.current_review`, with its kind and how many days overdue; when that form cannot be built it falls back to `Reviews due: <n>`), `First step:` (that review's first question), `Most overdue by kind:` (the most overdue weekly, monthly and quarterly review), `Focuses` (every live focus worst-first with its light and tier, and whether any still carries last quarter's tag, meaning the re-pick is due), `Feature use, last 30 days:` (each feature's count and verdict from `feature_use.build`, on-demand features left out), `Next today:` (the next timed event left today in the calendar cache), `Needs you:` (the top two `needs_you` rows), `Last Trello sync:` (`data/.trello-last-sync`, written by every writeback on that machine; git-ignored). It is rewritten on every render, and it is absent while `build_home` fails.
  - The verdict, `🔴 Body first: <verdict>`, with tonight's move, last night's sleep and awake minutes, and a broken night in its body (`home_data` `pulse` and `body`).
  - **The rating card**, interactive, the web's "How was yesterday?" card on the phone, shown only while the day the home page rates is unrated (`home_data` `rate_target`: yesterday before 6 PM, today from 6 PM). Titled `⭐ How was yesterday? <Sun Jan 5>` (`today` from 6 PM), with three checklists, Energy, Mood and Focus, each holding 1 to 5. When each list has exactly one tick, the next sync (`trello_writeback.sync_rating`, part of every writeback) saves the day through `pfc_writes.rate_day`, the web's writer: rating is the three averaged and rounded, hyperfocused stays unasked. A list with no tick waits; a list with two ticks is never guessed, and the card's description names it (`⚠ Mood has 2 ticks (3, 4)`). Only today or yesterday is saved, as on the web. Once the day is rated the card leaves the board. The card's id carries the date (`rate-day-<date>`), so a new day swaps in a fresh card.
  - One card per lever off target last night, worst first: `🔴 Sleep hours: 6.1h · target >=7.4h · on target 3 of 30 nights` (the levers, targets and the 30-night count are `home_data` `pulse`, from `pulse.py`; set the levers from your own `/pfc-analyze-trends` results).
  - `🟢 <n> on target last night`, the green levers folded into one card, as the web folds them.
- `✅ The 2+1` — the web 2+1 band. Today's undone picks first, critical then the bonus (interactive, mark complete from the widget), then from 6 PM `Tomorrow, <day>: <titles>` (or `no picks set yet`), then ONE card for the rest of the band, because extra cards in a list you tick off are clutter: `🔴 What needs you: <n>` (`needs_you`, the due review, the one thing `tour_look` says to look at), or `ℹ️ Why today, and hand-offs` when nothing needs you; its description holds those rows, the `Why: <focus> → <vision> → <value>` line (`focus_of_day`) and the tasks an agent can do (`handoffs`). Pick cards use the task title format below, with ` · <project>` for a task in a project. Ticking one of the read-only cards does nothing: the writeback acts only on task and habit cards.
  - **The system picks the 2+1 when you have not.** Every writeback ends with `trello_writeback.auto_pick_today`: before 6 PM on a day whose `daily-focus.ndjson` record holds no pick, it sets today's picks from the home page's own suggester (`home_data.build_home` `suggested`, taken by `home_data.auto_picks` the way the suggestions card takes taps: first two critical, third the bonus; agent-doable, deferred and blocked tasks are never offered) through `pfc_writes.set_picks` with `source: "auto"`. It never touches a record that holds picks, runs once per day (`source: "auto"` marks it), and stops for the day once you drop a pick.
  - **Archiving a `✅ The 2+1` card in a Trello client drops that pick** (`sync_dropped_picks` reads the board's archive actions since local midnight; only an archive with no `appCreator`, which is what a person in a Trello client makes, counts, so the render's own archives never do): the task leaves today's `critical`/`bonus`/`project`, goes into the day's `skipped` and `dropped`, and stays open in the backlog, so the next render shows it in `✅ Tasks` again.
- `☀️ Habits` — interactive, the web Habits band: daily habits, then monthly ones. Titles use the habit's `short` name from `config/habit_schema.yaml` (the full description when it has none) plus a running count: daily cards show `<done>/<target> past 7 days` (the same trailing window and skip-adjusted target as `focus_status.habit_rate`, so the card agrees with the habit's light), monthly cards `<done>/<target> this month`. A tick logs the day it was ticked, so an evening habit forgotten until morning goes through the web page or chat, not the card. Auto-derived habits (`auto_derived: true`, daily or monthly: a sleep habit read from a wearable, the calendar-derived ones) get no card, because a manual tick would outrank the measurement.
- `🗓️ Week` — the web Week band: one card per day of the next seven (`home_data.week_days`), titled `Today: 12:00 PM Lunch · 3:30 PM Dentist` or `Mon Jan 6: …`, the first three events in the title and the rest counted (`· 3 more`), as the web folds them; the body lists every event. It answers "what's happening this week that I wouldn't have guessed": recurring commitments DO show (they are most of the week), while PFC scaffolding, personal routines and fixed weekly patterns are hidden — but a **one-off** carrying a pattern's title still shows, because the exception is the point. Four filter lists in `config/trello_calendar_filters.yaml`, shared with the web and the TRMNL week screen; the `exclude_prefixes` list is the deterministic escape hatch (rename an event `Task - …` or `Routine - …` and it drops off without a new rule).

**This quarter**

- `🎯 Focuses` — every live focus by tier (🧱 Foundations, 🎯 Active Pursuits, 🎧 Currently Consuming), the impact/urgency code first, with the derived focus light (`focus_status.status_rows`, the web Focuses band's light), not the stored `status` field, which only a `focus_status.py --write` run refreshes; parked ones show 🅿️.
- `🛠️ Projects` — the web Projects band's active projects plus the project gauges from `project_gauges.py` (carried on `home_data`'s project rows): `🔴 30% Name · idle 3d`. The circle is the on-time velocity light and appears only for a project with a deadline; `stalled` replaces `idle` at 14 days. Description: pace and estimated finish, on-time line, days idle, next task, parts, area, values, priority (the priority stays as the label colour). Progress checklist (Part 1..N, completed parts checked) for the built-in Trello progress bar. Then `Parked and on deck (<n>)`, one card listing the rest, as the web folds them.
- `📈 Trends` — the web Trends band: one card per row (day rating, energy, mood, focus averages, picks done) with its 30-day light and why, e.g. `🔴 Picks done — 0 of 4 critical picks done`.

**Always**

- `🧭 Areas` — the web Areas band. First a plate card (`🟡 Plate: 110 of 112 free hours committed (98%)`) when the areas have time items, then one card per life-wheel area with its light (area items rolled up by `area_items.py`, else the manual light) as a title circle and a plain colour label; the description has the light's source, weekly hours, the note, the check-in date (stale flag), every item (light, Time or Status, hours, weight, why) and the area statement. Last, the household folded into one card as on the web: `🏠 Household: 4 of 10 rooms green · rated Thu Jan 2` (` · stale` when the web shows Stale), every room worst first in the body (`2-areas/_data/household-status.ndjson`; absent while `household_parked` is set).
- `💎 Values` — the numbered values from `1-values/values.md`, then `Question of the day: …` (`home_data` `question_of_day`).
- `🔭 Visions` — `Today's vision: …` (`vision_of_day`) first, then each active vision wearing the lights it borrows from what sits under it, never a gauge of its own: `🔴 Ship a side project — focus 🔴 Weekly build night · project 20%`. The lead circle is the worst live linked focus light, else the worst project on-time light; a vision with no live focus and no active project shows `⚪ <title> — dormant`, which sorts last.
- `🧠 Front of mind` — a small, cycling set of grounding anchors to keep front-of-mind right now. Life-wide but **critical-only** — genuinely load-bearing stuff, not trivia/reference. Rendered from `data/grounding.ndjson` (active entries), one card per topic with its points in the body. Soft-capped at `GROUNDING_CAP` (10) in `trello_render.py`: renders all active anchors but logs 🟡 if over cap (curate by retiring, never silent-truncate). Read-only.

**The web's other page**

- `✅ Tasks` — interactive, the web Tasks page on the phone: every open task, standalone or in an active project, in the web's default order (priority code, then age; held by a position built from the code and the task id), except today's picks, which sit in `✅ The 2+1`. A task in a project ends ` · <project>`. Deferred tasks and tasks of a parked, done or missing project stay off the board until they come back into rotation.

Findings, hypotheses, insights and supplements are agent-only, as on the web (`web/src/lib/data-files.ts` `AGENT_ONLY_DATA`), so the board has no list for them. Lists from the older board layout (`🦸 Superman Pulse`, `🎯 Current Focus`, `✅ 2+1`, `☀️ Daily Habits`, `🌙 Monthly Habits`, `🗓️ Week at a Glance`, `⬅ Last 7 Days`, the per-project `🎯 <Project>` lists, `💡 Insights`, `📜 Findings`, `🧪 Hypothesis`, `💊 Supplements`) are no longer rendered; archive them by hand once, or run `--rebuild`.

## Card conventions

- Card identity lives in description frontmatter: `---\npfc-id: <repo id>\npfc-type: <type>\n---`. The render parses on read-back; user edits to body get overwritten on next render.
- Cards carry a position (`Card.pos`), set on create and enforced on every render, so a red-first order holds after a light changes; a card without one stays wherever it is.
- Task / 2+1 / Project cards use plain (unnamed) priority labels in 5 colors — red (AA), orange (AB/BA), yellow (AC/BB/CA), green (BC/CB), purple (CC). The exact 9-tier impact×urgency code stays visible in titles like `AA (M) - <description>` for sorting; the label conveys priority severity only. Tasks an agent can run start to finish get ` 🤖` after the size.
- Tasks/projects with deadlines populate Trello's `due` field at noon UTC; the Mark Complete checkbox is the bidirectional write-back surface.
- See `automations/scripts/trello_helper.py` (full Trello CRUD), `trello_render.py` (render engine), `trello_home.py` (the cards built from the web home page's data), and `trello_writeback.py` (sync engine; its mutations live in `pfc_writes.py`, shared with the web writer `web_write.py`).
