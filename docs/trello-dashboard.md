# Trello dashboard

The full reference for the Trello board. The root `AGENTS.md` keeps a short summary, so the always-loaded instructions stay small; read this page before changing anything that renders to Trello.

The PFC system mirrors to a Trello board (id in `TRELLO_DASHBOARD_BOARD_ID`) so you can see the whole system at a glance from your phone. Repo is canonical; Trello is a rendered cache for read-only lists, with a thin write-back path for cards you check off from the mobile widget. Setup: [`install/trello.md`](install/trello.md).

Three skills + one helper script:

- **`pfc-trello-inbox`** — process the `📥 Inbox` list. You dictate quick captures from a phone widget; the skill walks each card, treats the title as if you'd typed it in chat, runs the natural action, deletes the card.
- **`pfc-render-trello`** — refresh every dashboard list from current repo state. Idempotent; running twice = 0 changes. Auto-fetches Calendar (primary + work) via MCP; the week surface hides PFC scaffolding, routines and known weekly patterns while keeping their one-off exceptions (`config/trello_calendar_filters.yaml`). Includes `--rebuild` for full re-creation and `--reset-list <name>` for single-list resets, both confirmation-gated. The `📥 Inbox` list is hard-excluded from every render and rebuild. Auto-invoked as a fail-safe step (any error logs 🟡 and continues; never blocks anything) on three triggers:
  - **Calendar-fetching renders (refresh `🗓️ Week at a Glance` too)** — the one path that fetches Calendar via MCP before rendering: `pfc-render-trello` (manual/on-demand; `/pfc-review` and `/pfc-yearly-checkin` call it too).
  - **Bare skill-driven renders (skip the live Calendar fetch)** — wired as a fail-safe end-step but run the bare `trello_render.py` (no MCP fetch), so they refresh every repo-fed list: every `pfc-add-*` skill, `pfc-supplement`, `pfc-complete-task`, `pfc-log-habit`, `pfc-log-day`, `pfc-sync-trello` (when counters show writes), and every web UI write (`web_write.py` starts the render after its push).
  - **Git post-commit hook** — `.githooks/post-commit` (installed at `.git/hooks/post-commit`) catches ad-hoc edits that bypass skills: raw `jq` updates, manual file edits, agent edits, anything else that commits a rendered file. Triggers when any of these change: `1-values/values.md`, `2-areas/_data/*.ndjson`, `2-areas/*/statement.md`, `3-visions/*.md`, `4-focus/_data/focus.ndjson`, `5-projects/_data/projects.ndjson`, `6-tasks/_data/{tasks,tasks-archive,daily-focus}.ndjson`, `7-habits/_data/habits-{daily,monthly}.ndjson`, `data/{grounding,insights,findings,hypotheses,supplements,day-tracking}.ndjson`, `config/habit_schema.yaml`. Opt-out: `PFC_SKIP_TRELLO_RENDER=1 git commit ...`.

  A render without a live Calendar fetch (the post-commit hook, a scheduled render, a bare skill render) falls back to `data/calendar-cache.json` for `🗓️ Week at a Glance`, which the daily sync job refreshes every morning (it runs `/pfc-render-trello` Step 1 alone). A cache older than 7 days, or one with no upcoming events, is skipped with a 🟡 line; `--no-calendar-cache` turns the fallback off. (Email is not a rendered list — labeled emails become tasks via `pfc-email-triage` Step 0.)
- **`pfc-sync-trello`** — process cards you marked complete (`dueComplete: true`). For tasks: marks done in repo (and ticks that day's `daily-focus.ndjson` record when the task is one of its picks), archives the card. For habits: logs the habit (a missed row for that day is marked done in place), leaves the card to cycle on next render. Idempotent. Run every morning by the daily sync job (`scripts/daily-sync.sh`, which calls `trello_writeback.py sync`). When run standalone with non-zero counters, also auto-renders the board so card state catches up.

The dashboard board hosts these lists (user-managed naming, do NOT rename):

- `📥 Inbox` (managed by `pfc-trello-inbox`, never touched by render)
- `🧠 Front of Mind` — a small, cycling set of grounding anchors to keep front-of-mind right now (the most important things to stay grounded in). Life-wide but **critical-only** — genuinely load-bearing stuff, not trivia/reference. Rendered from `data/grounding.ndjson` (active entries). Soft-capped (`GROUNDING_CAP` in `trello_render.py`): renders all active anchors but logs 🟡 if over cap (curate by retiring, never silent-truncate). Read-only surface; not interactive.
- `🦸 Superman Pulse` — the levers that drive your best days, as an at-a-glance status board: one card per lever (`{🟢/🟡/🔴} [TIER] {lever}: {value} (target {t})`) plus a verdict card, sorted red-first, with the CRITICAL/MODERATE tier only breaking ties inside a colour. Rendered from the latest `data/day-tracking.ndjson` record by `render_superman_pulse` in `trello_render.py` (lever definitions and thresholds live in `automations/scripts/pulse.py`). The lever set and targets should be grounded in your own good-day-vs-average-day data (see `/pfc-analyze-trends`); a metric that doesn't separate your best days from your average days doesn't earn a card. Read-only mirror of the `pfc-daily-summary` Superman Pulse section. Auto-refreshes whenever day-tracking changes (day-tracking is a post-commit render trigger).
- `🎯 Current Focus` — the Focus layer (`4-focus/_data/focus.ndjson`), tiered and traffic-lit. Read-only; managed via `/pfc-focus`.
- `✅ 2+1` and `✅ Tasks` — interactive (mark complete from widget). `✅ Tasks` shows ONLY standalone tasks (no project linkage); project-linked tasks render to per-project lists below. A task with `agent_doable: "yes"` carries 🤖 in its title, so the hand-off batch is visible at a glance.
- `🎯 <Project Name>` — one list per **active** project. Each holds that project's open task backlog (excluding tasks pulled into today's 2+1). Created automatically when a project is `active: true` in `projects.ndjson`; archived automatically when the project flips inactive. Tasks linked to inactive/paused/done/missing projects do NOT render to Trello (they stay in NDJSON until the project reactivates). Interactive — mark complete from widget like Tasks cards.
- `☀️ Daily Habits` and `🌙 Monthly Habits` — interactive
- `🗓️ Week at a Glance` (calendar, sorted chronologically). Answers "what's happening this week that I wouldn't have guessed": recurring commitments DO show (they are most of the week), while PFC scaffolding, personal routines and fixed weekly patterns are hidden — but a **one-off** carrying a pattern's title still shows, because the exception is the point. Four filter lists in `config/trello_calendar_filters.yaml`; the `exclude_prefixes` list is the deterministic escape hatch (rename an event `Task - …` or `Routine - …` and it drops off without a new rule).
- `⬅ Last 7 Days`, `💎 Values`, `🧭 Areas` (life-wheel surfaces here as a plain color label, not a separate list), `🔭 Visions`, `🛠️ Projects`, `💡 Insights`, `📜 Findings`, `🧪 Hypothesis`, `💊 Supplements`

Key conventions:
- Card identity lives in description frontmatter: `---\npfc-id: <repo id>\npfc-type: <type>\n---`. The render parses on read-back; user edits to body get overwritten on next render.
- Project cards carry a `Progress` checklist (Part 1..N, completed_parts checked) for the built-in Trello progress bar. Title also shows `[<percent>%]`.
- Task / 2+1 / Project cards use plain (unnamed) priority labels in 5 colors — red (AA), orange (AB/BA), yellow (AC/BB/CA), green (BC/CB), purple (CC). The exact 9-tier impact×urgency code stays visible in titles like `AA (M) - <description>` for sorting; the label conveys priority severity only.
- Tasks/projects with deadlines populate Trello's `due` field at noon UTC; the Mark Complete checkbox is the bidirectional write-back surface.
- See `automations/scripts/trello_helper.py` (full Trello CRUD), `trello_render.py` (render engine), and `trello_writeback.py` (sync engine; its record changes live in `pfc_writes.py`, shared with the web writer `web_write.py`).
