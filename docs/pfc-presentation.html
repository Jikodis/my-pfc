PFC = prefrontal cortex — the part of the brain that plans, initiates, and follows through.
Why build this

Executive function is the scarce resource

Every productivity app assumes…

  • You will open the app
  • You will remember why the item is there
  • You will plan, prioritize, and review on your own
  • The app owns your data, in its format

This system inverts that

  • An agent operates the system — you converse with it
  • State lives in files you own, in a Git repo
  • Planning, reviews, and nudges are pushed to you
  • Apps become rendered views, never the source of truth
Design principles

Five rules the whole system follows

  • The repo is canonical. If it matters, it lives in a file. Everything else is a cache.
  • File-based truth over hidden memory. The agent never relies on chat history for durable state.
  • The agent is an operator, not the owner. All state stays visible, greppable, and hand-editable.
  • Idempotent automation. Every render and fetch can run twice safely — which makes aggressive scheduling free.
  • Forward-moving. Retired mechanisms are deleted, not preserved. Git history is the audit trail.

Data layer

Three formats, one write discipline

FormatUsed forWhy
MarkdownValues, area statements, project notes, docs, skillsProse humans edit
NDJSONTasks, habits, projects, day tracking, event logsOne record per line — append- and diff-friendly, jq-queryable
YAMLSchemas and configurationEvery NDJSON file has a schema to validate against
# every structured write goes through jq: temp file + atomic rename
jq -c 'select(.id != "…") …' tasks.ndjson > .jq_update.tmp \
  && mv .jq_update.tmp tasks.ndjson

No raw string appends, no sed on structured data. Records mutate in place — Git carries the history, so the live files stay small and current.

The operator

Claude Code is the runtime

◆ Skills

38 slash-command workflows (/pfc-*) — each a Markdown file of instructions the agent follows verbatim. Versioned prompts, reviewed like code.

◆ Hooks

Shell scripts the harness runs at session start, on every prompt, after every file edit, and at end of turn — injecting context and enforcing rules the model can't skip.

◆ Connectors (MCP)

Google Calendar, Gmail, and Drive via Model Context Protocol — schedule awareness, email-to-task triage, spreadsheet output.

Chat is the primary UI — from a laptop terminal or a phone via remote control. "Add a task", "what should I work on", "run my evening check-in" are all just conversation.

Cadences

Reviews drip — they don't pile up

The usual failure

Weekly / monthly / quarterly review rituals demand an hour of a resource the system exists to conserve. Skip two and the backlog is demoralizing; the ritual dies.

The replacement

Every review type lives in a ledger with its own cadence — stale-task triage, life wheel, project progress, focus accuracy, trend analysis, quarterly re-picks…

  • The evening check-in serves at most 2 due items per night
  • Each takes a minute or two inside a ritual that already happens
  • A catch-up command clears the whole backlog when wanted
  • Nothing is ever "overdue by six weeks" — just next in line
Guardrails

Letting an LLM write your data — safely

  • Schema validation on every commit. A pre-commit hook runs ~19 check groups: NDJSON parses, schema conformance, cross-file referential integrity, future-date detection.
  • Validation after every edit. A post-edit hook re-validates touched data files immediately and forces the agent to fix failures before moving on.
  • Date injection. The server clock is UTC; hooks inject the local date at session start and on every prompt, so date-stamped records never silently shift a day.
  • End-of-turn ledger. A stop hook prints uncommitted state files, so "done" claims get reconciled against Git, not memory.
  • Commit policy. Routine data writes auto-commit and push; structural changes require explicit approval.

Surface · phone

Trello as a declarative UI

  • A render script reads ~16 repo files and computes the desired board, then diffs against the live board and applies only the minimum API calls
  • Card identity lives in description frontmatter (pfc-id), so renders are idempotent — a no-change run is a no-op
  • Write-back: checking a card's Mark Complete box from the phone widget completes the task or logs the habit in the repo on the next sync
  • An Inbox list catches dictated quick-captures; the agent later processes each card as if it were typed in chat

Surface · wall

E-ink screens from repo data

  • TRMNL e-ink device polls an HTTPS endpoint on the VPS right before each screen refresh
  • A tiny stdlib Python server builds the payload per request from current repo state — the wall is as fresh as the moment you look at it
  • 13 plugins: today's focus, habits, projects, trends, weekly calendar, slipping work, and more
  • Shape data in Python, not templates — Liquid markup just prints pre-formatted values
  • Local preview renders 4-bit PNGs before any deploy — lint checks rules, eyes check layout

Data out

Running experiments on your own life

1 Track

Every day gets a 1–5 rating plus the auto-fetched health block — sleep, exercise, recovery — in one NDJSON record.

2 Analyze

A stats script computes correlations and effect sizes: which levers actually separate a great day from a mediocre one.

3 Learn

Claims live as hypotheses with evidence attached over time; confirmed ones graduate to findings the agent cites when giving advice.

The agent also watches for slippage — stalled projects, focus picks that never land, habits quietly failing — and raises them before they're weeks old.

Tech choices

Aggressively boring on purpose

  • No database, no web framework, no dashboard app. Flat files + Git cover state, sync, backup, and audit history.
  • Python standard library almost everywhere. Two dependencies total (YAML parsing, spreadsheet output). HTTP is urllib; the web server is http.server.
  • Every integration is a rendered cache with one canonical direction — plus exactly one narrow write-back path (the phone check-off).
  • Secrets in one gitignored .env; tokens never touch the repo; the e-ink endpoint is bearer-authenticated and loopback-bound behind the proxy.
  • Tests and audits for the plumbing: a pytest suite for the automation scripts, and skills that audit the system's own health.
Takeaways

What transfers to your own build

  • Make the agent the operator, not a chatbot bolted onto an app — conversation is a better interface than forms.
  • Plain text in Git beats every productivity app for longevity, portability, and agent-operability.
  • Idempotency is the keystone — it turns risky automation into something you can run every two hours without thinking.
  • Guardrail the model with hooks and validators, not hope. Enforce schemas where the agent can't skip them.
  • Design for the brain you have — one daily ritual, dripped reviews, external triggers, ambient displays.
